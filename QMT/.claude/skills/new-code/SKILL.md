# New Code Skill

## Overview
当用户要求新建代码时，**严格按以下步骤执行，不要跳步**。

## Step 1 — 复述需求
- 用自己的话重述用户需求
- 列出输入 / 输出 / 边界条件 / 依赖
- 若有不明确点，**必须先问用户，不要猜**

## Step 2 — 给方案，等确认
- 给出代码结构（文件、函数、类）
- 给出关键设计决策（用啥库、为啥这么拆）
- 给出与现有项目的衔接点
- **输出方案后停住，等用户说"可以写"再进 Step 3**

## Step 3 — 写代码
- 首先实现一份伪代码，让用户确认无误后开始编写
- 按确认的方案实现
- 每文件 / 每函数简短注释
- 代码尽可能简短易懂，不需要考虑太多极端复杂的情况
- 不要在方案未确认时提前写

## Step 4 — 自测（必须）
- 写一个简单的测试（unit test / 脚本 / 最小可运行 demo 都行）
- 能跑、能断言、能看出对错
- **测试必须实际跑通**（用 Bash 调），不能只"看上去对"
- 若测试失败，回到 Step 3 修，直到跑通

## Step 5 — 示例
- 给出程序运行方式, 用户直接拿来就能跑
